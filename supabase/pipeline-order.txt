# The Production Pipeline SQL files the Pipeline deploy workflow (.github/workflows/pipeline-deploy.yml) applies, in
# this order, as the database role pipeline_owner. One file name per line; # starts a comment.
#
# - A file is applied whenever its text differs from the last copy the workflow applied (it keeps a sha256 of each in
#   public.pipeline_sql_applied), each file in its own transaction. Every file must be safe to re-run.
# - Order matters: a file may use only what is already live or what a file above it defines (Postgres checks function
#   bodies when they are created). A new file goes at the end unless something above needs it.
# - Every supabase/pipeline-*.sql must be listed here, except *-verify.sql checks, which the workflow never runs.
# - Start each file with "set role pipeline_owner;" and end it with "reset role;", so a run from Gianni's Mac also
#   leaves everything owned by pipeline_owner.
# - Define each table, function and policy in one file only.
# - Files that need postgres (roles, cron schedules, the M1 lockdown) live in supabase/postgres/ and are applied once
#   from Gianni's Mac, never by the workflow.

pipeline-access.sql        # pipeline_jwt_email(), pipeline_viewers, pipeline_source()
pipeline-batches.sql       # pipeline_can_view(), which every page table's policy uses
